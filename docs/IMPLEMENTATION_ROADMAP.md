# AI Agent Hub — 開発ロードマップ
更新: 2026-11-17
状態: **開発方針・受け入れ条件**。実装済みを意味しない。

## 成果目標
- オーナーがAI社長との会話で事業目標を伝える。
- AI社長→部長エージェント→実行AIがタスクを分担。結果を保存し、社長が報告する。
- CrowdWorks運営システム、My Addness、将来の事業はそれぞれ別の業務アプリとし、共通Hubから接続する。
- プロバイダの制限、運用費、承認、安全性を最初から考慮し、成果を検証可能にする。

## フェーズ0: 棚卸し
- [ ] 既存ファイル、開発言語、CI、環境変数、実行環境、認証方式を確認
- [ ] 現在の動作と未実装機能を証拠つきで分類
- [ ] 秘密情報・APIキーはリポジトリにコミットしない

## フェーズ1: 動く土台（最優先）
- [ ] 永続タスク保存（タスクID・親子関係・期限・優先度・実行者・状態・履歴）
- [ ] 状態遷移と重複実行防止（idempotency key / lease）
- [ ] モックAI社員ワーカーへの自動振り分けと結果の取り込み
- [ ] APIの上限・タイムアウト・429を模擬して再試行、停止、復旧
- [ ] 監査ログと操作承認ゲート（外部送信・契約・課金等）
**受け入れ:** 模擬案件を投入→振り分け→実行→検品待ち→完了まで到達し、途中再起動後も状態・成果物が保持される。

## フェーズ2: AI組織
- [ ] 部門ロール（営業/制作/品質管理/管理）と責任範囲を機械的に定義
- [ ] 依存関係に応じた並列実行、競合防止、タスク間引き継ぎ
- [ ] AI同士の相談・レビュー・修正の回数上限、費用上限
- [ ] GPT/Codex/Claude Codeなど利用可能な接続方式を権限・利用規約・費用で検証
- [ ] 自動検品（要件照合・テスト・根拠記録）と人間へのエスカレーション
**受け入れ:** 一つの模擬案件を複数のAI社員が並行担当し、検品NGで修正に戻り、検品OKのみ完了となる。

## フェーズ3: AI経営
- [ ] 目標→計画→案件選定→実行→業績評価のループ
- [ ] 売上・粗利・作業時間・失敗・再作業の可視化
- [ ] 自己改善は検証可能な提案→小規模テスト→承認・採用の順で行う
- [ ] スマホで案件、担当、進捗、保留理由、費用、成果物を一覧表示
- [ ] CrowdWorks業務アプリとの接続テスト。外部操作は権限内だけ。
**受け入れ:** 模擬の月次売上目標を入力し、根拠ある計画と各AIの実行状況・未達理由がダッシュボードと社長報告に一致。

## 開発ルール
- mainを直接変更せず、作業ブランチ→テスト→レビュー→統合。
- 新しい課金、契約、外部公開、外部送信、重要な破壊的変更は事前承認。
- 実装済み・テスト済み・未確認を区別し、実際の成功ログを受け入れ証拠とする。
- 利用上限のための自動再開は、制限回避・規約違反になるような方法を使わない。
- 次の具体的な開発タスクは **フェーズ0の棚卸し**。続いてフェーズ1のタスクストアと状態遷移を小さく実装する。
