# AI Agent Hub — 運用設計 v1
作成日: 2026-11-17
状態: **設計のみ**。この文書の存在は自動実行・API連携の稼働を意味しない。

## 目的・境界
- AI Agent Hub は事業横断で使うAI実行基盤。CrowdWorks会社運営は別リポジトリの業務アプリとして接続する。
- オーナー→AI社長(GPTによる統括ロール)→部門エージェント(営業/制作/品質/管理)→実行ワーカー(Codex/Claude Code/GPT等)。
- 役職はモデル名ではなく**権限を持つ役割**として定義する。部長は担当範囲内でタスク分解・振り分け可。
- チャット会話自体は常時起動の制御プロセスではない。スケジューラ、ワーカー、状態DB、認証済み連携が別途必要。

## タスクの状態遷移
`created -> screened -> queued -> running -> reviewing -> completed`
例外: `awaiting_approval`, `rate_limited`, `retry_scheduled`, `blocked`, `failed`, `cancelled`
各遷移に時刻、実行主体、証拠リンク、エラー分類を記録。重複実行を防ぐ冪等キーを持つ。

## 最小タスクレコード
- task_id, project_id, parent_task_id, department, owner_role, executor, type
- priority, due_at, expected_revenue, estimated_cost, budget_cap
- state, attempts, next_retry_at, lease_until, idempotency_key
- input_ref, output_ref, verification_ref, approval_id, audit_log

## 利用上限・障害対策
1. プロバイダ別・アカウント別に同時実行数、利用枠、予算上限を設定。利用可能枠が取得できない場合は保守的に制限。
2. 429/一時障害は指数バックオフ+ジッターで再試行。Retry-Afterを尊重。最大試行回数を超えたらblockedに移す。
3. API障害や枠超過時、キューに永続保存して再開。ユーザー操作を勝手に再送しない。
4. リース期限・心拍・タイムアウトで停止を検知。途中成果物を保存。
5. 代替モデルへの切替は予算とデータ取扱い許可の範囲内のみ。ChatGPT UIの利用上限をAPIから常に自動検知できるとは限らない。
6. 最終検品を通過するまで納品可能状態にしない。監査ログで実行結果を検証する。

## 権限
- 自動可: 内部タスク作成、優先順位調整、下書き、テスト、検品、内部ログと進捗更新。
- 要承認: 課金増額、契約、規約上の権限不明な応募・納品、外部送信、外部公開、秘密情報の共有、破壊的変更。
- 承認の可否は業務操作単位で記録。チャットでの一般的な委任を無制限の承認とみなさない。
- CrowdWorks案件: AI使用条件・面談要否・成果物品質・契約条件を案件ごとに判定。

## 実装順序と受け入れ条件
1. リポジトリ構造・既存コード・CI・シークレット管理を棚卸し。
2. タスクDB+状態遷移+監査ログ: 再起動後も状態が残る。
3. ワーカーインターフェイス+モック実行: 一つのタスクを二重処理しない。
4. レート制限+バックオフ+再開: 429/タイムアウトの模擬テストが通る。
5. 承認ゲート: 未承認の外部送信・課金がブロックされる。
6. GPT/Claude/Codexの実接続: 個別の権限確認とE2Eテスト後に有効化。
7. CrowdWorks運営アプリを別リポジトリで接続し、案件→制作→検品→管理を模擬案件で一巡検証。
8. ダッシュボード: 案件、担当、実行状況、保留理由、見込利益、成果物を一目で確認。
